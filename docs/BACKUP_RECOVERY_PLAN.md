## 1. 现状和保护对象

| 数据来源 | 入口及数据根目录 | 本轮状态 |
| --- | --- | --- |
| 浏览器正常试用 | Vite；项目 `.local-data/` 或既有试填目录 | 未读取、未备份、未接管；旧服务不遵守新锁协议 |

浏览器与 Electron 的数据不自动同步或合并。现有试用库仍为 `trial_state` 单行 JSON、`attachments` 元数据及 `operations` 请求表；新 managed 根目录另有账本 UUID，没有正式迁移版本或全量修订历史。删除批次的完整前值保留在 `batchEvents`。备份保存全部既有内容，不重建 JSON，不转换为规划中的正式模型，不伪造旧预支日期或缺失历史。

原来没有 `generation`／`resetReceipt` 的账本不回填字段。这两个可选字段属于技术元数据，不计作费用、报销或请求操作。恢复使用新账本 UUID，原始 generation 保持原值；客户端跨根隔离由 wrapper 处理。

后续受限费用纠错增加可选 `expenseEvents`，包含完整前后值、每笔修订及操作关联。备份校验修订连续、审计链、不可编辑字段不变、最后快照等于当前费用，并双向校验请求类型和时间；纠错后发生的合法报销不使旧纠错失效。旧JSON不补字段，清单版本及摘要字段不变；详见[纠错验证](EXPENSE_CORRECTION_VALIDATION.md)。

当前已验证页面导出与显式 CLI 两条路线：页面由持锁服务导出至启动时配置的本机目录；CLI 要先停止占用该新 managed 根目录的实例，再指定来源和本地目标导出、验证、恢复到新目录。活动写入者存在时拒绝，不自动关闭旧实例。目的地由用户指定，不默认云同步目录，不上传。Git、CSV 和报销材料包不能替代完整备份；真实资料与异盘介质本轮均未操作。

## 2. 已实现的备份格式

当前采用自包含目录，先在唯一 `.partial-backup-*` 暂存目录完成快照和校验，再以原子 `mkdir` 独占最终目标、逐项复制，最后发布 `COMPLETE`。没有以 `rename` 覆盖最终目录；既有目标即使为空也拒绝。压缩归档尚未实现。

```text
backup-<backup_id>/
  manifest.json
  database.sqlite
  attachments/<受管相对文件名>
  COMPLETE
```

`manifest.json` 当前包含：

- 格式 `qianlai-ledger-backup`、格式版本 `1`、备份 ID、源账本 ID、UTC 完成时间及应用版本；`sourceRevision` 当前为 `null`，未嵌入提交 SHA。来源只接受 `isolated-test`。
- 结构标识 `trial-state-json-v0` 和结构指纹；这是备份格式标识，不表示数据库已有正式迁移版本。未知表结构、索引、触发器或视图拒绝。
- 数据库及全部受管附件的相对路径、大小、SHA-256；附件是否登记、是否引用。合法孤立文件保留并标记，不自动挂接或产生费用。
- 费用、预支、有效／撤销批次、删除审计、分配、操作及附件数量；支出、预支、余额、本人垫付、已报销和待报销合计。金额使用 BigInt 汇总、记录为整数分十进制字符串。摘要只用于校验，数据库仍为事实源。

`COMPLETE` 保存清单 SHA-256 和备份 ID。无完成标记、未发布的 `.partial-*`、错哈希或未知版本均拒绝恢复。哈希用于发现损坏，不是加密或来源认证；不增加密码或密钥管理。完成标记之后若 fsync 失败，接口仍报错，保留并返回已生成目录供检查，不声称持久化成功。

当前上限为数据库 256 MiB、状态 JSON 64 MiB、清单 16 MiB、单图 20 MiB；超限停止。完整清单只留在备份内；Git 内报告只记合成结果，不复制真实金额、商户、绝对个人路径或截图。

## 3. WAL 一致性与已实现备份步骤

SQLite WAL 可能包含未写回主文件的已提交内容，不能只复制运行中的 `.sqlite`，也不能依次复制持续变化的主文件和旁文件充当一致快照。当前复用 `better-sqlite3` 的 `db.backup()`，没有新增依赖。接口背景见 [SQLite WAL 文件规则](https://www.sqlite.org/wal.html) 和 [SQLite Online Backup API](https://www.sqlite.org/backup.html)。

1. 校验明确来源、managed 标识和受支持结构，目标不能在源账本目录内。未知、残缺或未管理的旧目录拒绝，不能通过建空库接管。尚未实现可用空间预估；写入失败停止，不删除旧备份腾空间。
2. 持有 `.writer-lock` 与维护闸门。新版本第二个写入者被拒绝，维护期间不接受业务命令；关闭等待已进入的附件保存结束。CLI 不绕过活动实例的锁，残留锁不自动接管。旧服务不遵守新协议，所以本轮不直接备份其目录。
3. 源目录存在任意 `reset-journal.json`（含目录或悬空链接）立即拒绝，初始检查不读取业务；快照后、发布前再次检查。正常路径以只读既有连接生成 `.partial-backup-*/database.sqlite`，不清空源 WAL、不删源旁文件。
4. 从快照读取附件元数据并复制原件，核对大小和 SHA-256；缺失或损坏即失败。合法无引用文件保留，不自动关联；符号链接、硬链接、目录外路径和未知布局拒绝。
5. 只在副本上规范化为独立数据库，检查结构、完整性、业务关系及金额摘要，确认脱离源 WAL／SHM 仍可重开。不改源库，锁保持到校验完成。
6. 校验暂存副本，写清单，再排他创建最终目录，禁止覆盖地复制文件，最后发布 `COMPLETE` 并同步。发布瞬间出现竞争空目录时拒绝，已通过竞态测试。
7. 返回目录、备份 ID 和摘要。发布前失败只清理本次拥有的输出；完成标记后的同步错误保留目录并明确报错。源库、附件及旧完成备份不动，CLI 关闭只读连接后释放锁。

Mac 合成实例正常 SIGTERM 关闭后释放锁已验证。SIGINT、强杀和断电未验证；Vite 自动热重启不支持，不能假定其会完整等待并释放旧实例资源。Windows 目录 fsync 和持久性尚未验收。

## 4. 已实现的新目录恢复与业务核对

恢复仅接受尚不存在的新目录，不覆盖、不自动切换、不修改启动配置。先验证备份，再在暂存目录复制；用 `readonly:true,fileMustExist:true` 检查已有库，不调用会自动建库的 `createLedger()` 探测未知备份。

- 验证版本、结构和文件全集，拒绝绝对路径、`..`、重复名称、大小写冲突及链接。附件限定受管单层文件名。`integrity_check` 通过后继续校验业务，不能仅凭数据库物理完整性接受恢复；相关接口见 [SQLite integrity_check](https://www.sqlite.org/pragma.html#pragma_integrity_check)。
- 校验安全整数分、类别、日期、ID 唯一性、费用引用、分配唯一及正数、有效累计分配上限。批次没有独立金额字段，按分配求和。删除审计的完整前值与请求关系、已撤销批次和操作记录全部保留。
- 可选 generation 必须为 UUID；resetReceipt 只允许 `requestId`、`fromGeneration`、`at`，要求新 generation 与 fromGeneration 不同。它不要求已清空操作表保留回执请求，不计入业务摘要；错类型、缺字段、非法时间或额外字段拒绝。
- 比较完整费用、预支及元数据、批次、分配、审计、操作和附件，逐项比较资金事实及余额。已删除批次不会因恢复而复活；恢复不产生收支、不重新 OCR、不修改原始 JSON。
- 旧预支没有日期时不补写；已有日期、备注、操作时间和附件标识原样保留。尚未实现的退款、退还预支、发票关系及历史不在恢复时臆造。
- 任一校验失败即停止，不提供“忽略错误强制恢复”。合法孤立文件继续保留，不自动关联。

恢复发布同样用原子 `mkdir` 独占目标，`managed-ledger.json` 最后写入，分配新账本 UUID；数据库副本字节及原始 generation 不改写。不恢复旧锁或未完成清空日志。同一备份可恢复到两个不同新目录，这不是撤销单条批次删除操作。

## 5. 覆盖恢复、迁移和失败回退（待实现）

真实覆盖恢复须先展示来源、目标、备份时间和核对摘要，并取得对应操作授权。随后先为目标现用账本完成一份按上述流程验证过的全量备份；失败就停止覆盖。恢复暂存目录、回退目录及切换步骤应在同一文件系统内，跨盘输入先复制到本地暂存并校验。

拟定切换协议：

1. 持有跨进程维护锁，关闭目标全部 SQLite 连接和附件文件句柄，暂停正常账本启动；先检查是否有上次未完成恢复。
2. 将已验证的新数据放入目标旁的唯一暂存目录，持久化恢复日志，记录 `prepared`、原目录、暂存目录和回退目录的标识。
3. 原目录改名到回退目录，记录 `old-preserved`；新目录改名到目标，记录 `new-installed`。两次改名不是一个原子事务，必须分别记录并验证断电／崩溃时的恢复路径。
4. 在仍禁止业务写入时完成重开、附件及金额一致性检查，成功后记录 `verified` 并恢复入口。原目录和覆盖前备份继续保留，不在同一操作中删除。
5. 任一步骤失败就停止业务启动，恢复原目录为活动目录；若回退也受占用或权限阻挡，保持两份目录与日志不动并报告，不能自动创建空库。下一次启动先处理恢复日志，不让普通建库路径抢先运行。

迁移是单独的版本转换，不能隐含在备份或恢复中。先验证源全量备份，再在副本上转换并核对完整事实与附件；通过后才采用上述切换流程。失败继续使用旧版本和原账本，不原地破坏性升级。当前没有迁移框架，本方案不开展 JSON 试用结构到正式关系表的转换。

Windows 的目录改名、文件占用、权限、落盘与启动恢复必须实测；不能用 Mac 的改名成功宣称 Windows 崩溃安全。

## 6. 备份频率、保留与尚待确认事项

当前提供手动备份，保留旧完成备份。按日自动备份、异盘副本和轮换未实施；覆盖恢复与迁移的强制前置备份属于第 5 节未来流程。目标、频率、保留数量及可接受数据损失窗口仍需按实际使用明确，不预设自动复制或删除。

主动清空账本是独立操作，备份完成不会自动清空；清空接入验证另记。正常使用入口、试用数据保留、真实备份目的地和 Windows 测试机仍需确定。合成演练不代表真实账本已备份。
