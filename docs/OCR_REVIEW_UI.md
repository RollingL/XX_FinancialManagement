# 阶段 0 · 支付截图录入与附件（2026-10-12）

本文说明已接入的试用流程；唯一当前状态、历史结果和本轮验证边界见 [STAGE0_STATUS 顶部](STAGE0_STATUS.md#当前状态)。备份恢复仅有 [方案与验收清单](BACKUP_RECOVERY_PLAN.md)，未实现。

## 当前流程

主页仅保留“记一笔费用”，不再有独立“截图识别核对”。进入录入面板后选择 PNG/JPEG；展示原图、可放大查看，自动填写能够确定的实际支出金额、日期和商户。三项均可手动修正。上传新图先清空旧识别字段，失败或不确定时留空；不沿用今天或上张图的值。识别期间冻结字段，支持停止并改为手工填写。

“确认并保存费用”才会新增支出并复制原图为附件。取消/关闭不保存。详情可重开原图，刷新/重启后保留。上传和 OCR 本身不生成费用、收付款或报销。截图不自动视为发票。

## 字段规则

- 微信账单：高置信度“账单”、单个负号金额、明确支付成功/对方已收钱，并满足上下位置关系，才将负号金额转成正数支出分。不把所有负号数字直接当费用。
- 商户取主金额上方的账单标题；不取下方商户公司全称，也不硬编码商家名称。
- 日期只取“支付时间/付款时间/转账时间”的明确标签值，要求合法年月日；多个付款日期标签、低置信度或日期错误留空。不取收款时间或手机顶部时间。
- 余额、退款、原价、优惠均不作为支出候补；退款/入账/失败/外币截图不自动填成新支出。退款不自动净额冲减。
- 其他版式延用已验证的保守支付金额解析；暂未识别的商户/日期需手填。这不是通用票据识别完成。

## 保存边界

2026-10-12 用户授权从纯内存原型扩展到**独立本地试用账本**，不等于阶段 1 完成。首次创建为空账本，已有账本重开不清空，避免真实费用混入合成预支。预支录入尚未开放，起始余额为 0，可出现负余额。

- 浏览器开发：项目 `.local-data/trial.sqlite` 和 `.local-data/attachments/`。
- Electron 开发和打包应用：`app.getPath('userData')/stage0-trial/`。与浏览器目录独立，不自动同步；测试可由主进程环境变量 `XX_FINANCE_DATA_DIR` 指定隔离目录，网页不能选目录。
- SQLite 保存试用状态、附件元数据、请求摘要及操作时间；附件为受管副本，保留原始字节，读取时校验 SHA-256。原始用户文件不修改。
- 主进程或本机服务校验金额、日期、类别、图片魔数及实际解码、分配额度。保存采用 SQLite 事务和请求幂等；事务失败清理本次附件。进程在复制后事务前异常退出可能留下无引用副本，当前不自动清理，避免误删。
- 报销批次和分配随费用持久化；新增/撤销报销不改费用或预支。无手动“已报销”标签。
- 目前不支持修改已保存报销批次；请求幂等不是凭证查重，同图再次作为新费用确认仍可能形成另一笔支出。`operations` 仅有请求摘要、动作与时间，不等于完整修订历史。
- OCR 辅助进程只读取临时图片；Mac 使用 OS sandbox 禁止网络与文件写入，不能直接写账本。Windows 进程权限隔离尚未验证。保存附件时做独立解码校验，不再跑一遍 OCR。
- 仅向 localhost 开放开发服务；HTTP 校验 Host/Origin/自定义请求头；Electron 校验主窗口主 frame，渲染器没有 Node 或文件系统接口。开发服务器拒绝读取 `.local-data`；打包排除该目录。

暂未实现正式数据迁移、备份/恢复、预支录入、退款业务、费用编辑/删除及发票分配，不作为唯一财务存档。正式账本结构仍以实施方案为准，当前 SQLite 单行试用状态不是生产模型验收。
