## 参考与实际改动

核对本地 `A-雾紫白-低饱和-v2.png`：1586×992，SHA-256 `8341677a481547f4758d608dea54044ea2be1e20f627ae10786f97606cb35ffc`。未读取或使用后来更新的 Library v3，也未将参考图纳入源码。

保留 v2 的浅侧栏、上方三卡、左侧列表及右侧待处理层级；暖白与雾紫为主，主按钮 `#7562ad`，选中底色 `#eee8f8`。系统字体及内联 SVG，无新增依赖或远程资源。录入、报销、详情复用同一视觉语言。未完成业务入口明确禁用。

业务模型、数据库、IPC、OCR 服务、附件逻辑不变。卡片和待处理均使用当前账本数据；本月支出按当前自然月统计，资金余额与待报销按全账本统计。新增安全汇总用于录入金额预览，避免极值金额使格式化抛错而破坏整个界面；正式保存仍使用原有合计校验。

实测修复：模态框打开后明确聚焦金额／上传控件；表格滚动容器建立定位上下文，防止隐藏表头撑宽窄窗口；费用类别补充 group 语义。详情与表单标题在长内容滚动时保持可见。

## 隔离与执行环境

- 实测在用户这台 Mac：macOS 27.0.1（26A434），arm64；agent-browser 的独立 Chrome 会话 `xxfinance-v2-ui-20261012`。不是新交付的安装包。
- 原 127.0.0.1:5173 已有服务，本轮未接管、停止或向它发送测试请求。
- `/tmp/xx-finance-ui-v2-y49lhnfe` 是独立页面副本；只在副本把 Vite 端口、同源校验及 CSP 的 5173 改为 5187。项目的 Vite／持久化配置未改。
- 启动前确认新建 `ledger/` 为空；显式设置 `XX_FINANCE_DATA_DIR=/tmp/xx-finance-ui-v2-y49lhnfe/ledger`。没有使用默认 `.local-data` 或 Electron userData。
- 六笔费用由手工填写／测试 API 生成，名称带“合成演示”；第七笔使用仓库中明确合成的 `01_paid_balance.png`，在本机 OCR 后人工补全日期／商户并保存。
- 不读取、迁移、重置或上传真实账本；不读取 `.env`、密码、密钥；不上传源码或用户原截图。Library 仅新增五张上述隔离样例的界面截图。
