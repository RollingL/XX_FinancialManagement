## 已实现

- 预支导航查看到账记录；资金卡及预支页可打开新增面板，填写实际到账日期、金额、选填备注。日期默认设备本地今天，可修改。记录时间由业务层生成，与到账日期分开。
- 只记录已经实际收到的公司拨款，不发起转账；追加预支增加同一资金余额，接待／办公扣减共用资金。负余额显示本人垫付，补款不会自动核销费用。
- 前端从字符串解析整数分并校验安全范围；后端独立验证正整数分、日期、备注长度与累计预支安全范围，不能只靠前端。最大累计预支为 `Number.MAX_SAFE_INTEGER` 分，不允许靠费用抵消来绕过收入合计上限。
- 复用受限 HTTP／Electron IPC 命令通道与 SQLite immediate 事务；金额、元数据、请求摘要及操作时间同事务保存。相同请求幂等，同请求不同内容拒绝。请求幂等不等于银行交易查重，重新打开后再次手工登记仍会新增一笔。

## 无损兼容策略

`advances:number[]` 继续是预支金额的唯一事实源，资金公式未改；不将同一笔钱重复存成第二份金额记录。新增可选字段 `advanceDetails`，键是预支数组的零起始下标，值为 `{date,note,createdAt}`。界面编号为下标加一，不提供删除、重排或覆盖。

旧记录的金额、次序及其他原字段全部保留；不存在元数据时显示“日期未记录／旧记录，仅保留原金额／未记录”，不编造日期或操作时间。纯读取不添加字段、不改写 JSON；首次新预支保存才在同一个业务事务中追加金额与对应元数据。没有新增 SQL 表、ALTER、自动导入或正式迁移脚本。异常旧金额或元数据不通过新增校验时拒绝保存，保留账本，不静默删减。

这不是完整版本迁移框架，也不是降级／升级安装验收。未来调整数组结构或新增纠错、作废时，需先设计稳定来源关联、备份和迁移，不能直接删除数组项导致元数据错位。

## 同轮追加：费用支出按全账本汇总

用户明确要求所有“本月支出”界面改为“费用支出”，计算全部费用。`expenseSummary(expenses)` 直接接收完整账本，使用现有整数分 `sum` 分别计算总额及接待／办公拆分；没有使用当前月份、当前可见列表或日期截断。卡片增加“全账本”说明，原列表月份筛选与其他日期指标不变。

最小新增用例包含 2025-12-31、2026-09-30 和 2026-10-12 的四笔合成费用，合计 60007 分，接待 40004＋办公 20003 分，精确一致。实际隔离页面再追加两笔跨年／上月合成费用：费用支出 5069.12 元，接待 4012.34、办公 1056.78，余额 1930.89。类别及空关键词结果下卡片保持相同值。

原生月份控件的快捷填充、键盘和弹出选择在本轮自动化中未成功提交值，没有将其算作通过；随后通过 DOM 的原生 value setter 及 input/change 事件验证 React 筛选逻辑：月份 2026-10、列表只剩两笔当月费用，卡片仍含全部 5069.12 元。原生月份选择的人机交互本轮未验证通过。相关证据为 `expense-summary-tests.log`、`build-final.log`、`summary-ui-fixture.json` 和 `04-all-expenses-summary.png`。最终预支截图使用追加历史费用后的数据，因此与前面双击保存测试的余额不同。
