## 原错误与证据

此前实际查看截图确认二次启动错误为“账本正在使用或有残留锁”，不是端口冲突或OCR缺依赖的已证实错误。首次窗口2秒退出没有完整原机日志，不能倒推唯一根因。后续用户报告关闭 CMD 后出现残留锁；原锁实现也在合成子进程写入12345分预支并异常退出后稳定复现重开失败。

本轮消除对日常 CMD 的依赖，并对自身进程退出、残留锁与日志做完整处理；这不表示已在原 Windows 10 电脑重现首次2秒退出。

## 实现

- 根目录 `Qianlai.exe` 为原生 GUI 启动器，静态CRT；创建独立 Windows Job，原子加入主进程后才恢复执行，退出时清理所属后代。没有按进程名结束其他程序，没有关闭 Electron sandbox 或允许子进程 breakaway。
- 主程序单实例；重复启动回到已有窗口。关闭时先阻止新请求、停止OCR、等待已受理账本操作、关闭数据库、释放锁，再退出。关机查询空闲时不阻止系统结束；有未完成账本请求时请求收尾时间。系统强制结束仍可能打断收尾。
- 新锁核对机器、PID与创建身份，以SQLite操作系统锁串行获取／回收／释放。已确认失效的本机 owner 元数据保留在同一受管根下的 `.recovered-writer-lock-*` 目录；活进程、未知身份及外机锁拒绝接管。旧版无机器身份锁仅在受认可的本机便携根且PID不存在时允许恢复。
- 保留旧 `trial-data/user-data/stage0-trial` 入口与同级恢复根。接受旧包标识，不按构建编号重置数据。诊断CMD只在 `diagnostics` 写日志，不自建业务目录或绕开主程序配置。
- 完整备份／恢复保留开票提醒、旧发票历史与附件；恢复先备份原账本，再校验候选、原子发布新入口。未确认关闭的数据库连接不会提前释放锁。
- 正式界面移除阶段、试用及开发环境说明。删除已停用发票界面与写入代码；旧数据兼容校验保留。合成金额 fixture 移到测试目录，删除无调用的旧OCR表单辅助函数及其过时测试。
